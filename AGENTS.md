# AGENTS.md — Единая конституция разработки

Этот файл — **единственный источник правил** для всех ИИ-агентов (Codex, Gemini CLI, AI Studio и других), работающих с репозиторием **Historical Atlas Chronograph**.
Все остальные адаптеры сред (включая `GEMINI.md`) ссылаются на этот файл и не должны дублировать правила.

---

## 1. Обязательный порядок чтения перед началом задачи

Перед изменением кода или данных агент обязан прочитать:

1. `AGENTS.md` (этот файл) — базовые правила, команды и границы.
2. `docs/agent/DECISIONS.md` — принятые продуктовые, UX- и архитектурные решения (ADR). **Запрещено откатывать или молча пересматривать решения со статусом `Принято` без явного запроса пользователя.**
3. `docs/agent/HANDOFF.md` — текущее состояние проекта, последние завершённые задачи и открытые контексты.
4. Профильный документ по типу задачи:
   - Правки интерфейса, модальных окон, шапки или стилей → `docs/agent/DESIGN_SYSTEM.md`
   - Правки движка, кэширования, раскладки таймлайна или загрузки данных → `docs/agent/ARCHITECTURE.md`
   - Правки исторических JSON-веток (`public/data/`) → `BRANCH_SPEC.md` + `BRANCH_CATALOG.md`

---

## 2. Профиль проекта

- **Стек**: React 19, TypeScript, Vite, Tailwind CSS v4, Vitest, Lucide Icons.
- **Язык интерфейса и контента**: русский (строгий нейтральный академическо-редакционный тон).
- **Данные**: модульные JSON-ветки в `public/data/` с автообнаружением (подробности в `BRANCH_SPEC.md`).
- **Режим разработки**: dev-сервер на порту `3000`.

## 3. Жёсткие инварианты (нарушать запрещено)

### Дизайн и UX (подробнее: `docs/agent/DESIGN_SYSTEM.md`)
- **Тёмная музейно-редакционная эстетика**: фоны `#050811` / `#0b1325`, акцент `amber-400/500`, шрифты `Cormorant Garamond` (заголовки), `Plus Jakarta Sans` (текст), `JetBrains Mono` (даты и метрики с `tabular-nums`).
- **Без визуального шума**: запрещены статические плашки-«пилюли», декоративные/пульсирующие точки, левые цветные полосы `border-l-4`, вложенные карточки внутри карточек и инлайн-стили `style={...}` в стандартизированных досье-модалках.
- **Единый формат досье и карточек**:
  - `EraSummaryModal` и `WindowSummaryModal`: 4 вкладки (`Обзор`, `Лица`, `События`, `Культура и наука`), 5 сфер событий, 4 группы лиц с пояснением роли.
  - `CardDetailModal`: 3 вкладки (`Суть и этапы`, `Связи`, `Синхронные события`).
  - `ComparePeriodsModal`: 3 вкладки (`Сводка`, `Сферы и ветки`, `Связи и деятели`) и единая шапка `DossierModalHeader`.
  - `PersonDossierModal`: биографический лид, строчные ссылки на правления через `·`, поиск и пагинация по 12 записей.
- **Стабильная верхняя панель (`TopControlBar`)**:
  - Кнопка **«Вид»** никогда не выводит текстовые плашки статуса (`Компактно`, `Пропорц.`, `Без вех`) — только мягкая янтарная подсветка кнопки и текст в `title`.
  - Ширина всех кнопок навигации и фильтров фиксирована (без выезжающих бейджей на «Срез» и «Регион»).
  - На ширине `< 1280px` (`< xl`) панель работает в **2 компактные строки**, с `1280px+` (`xl+`) — в 1 строку. Кнопка «Анализ» всегда остаётся внутри экрана.
  - Все выпадающие поповеры шапки используют динамическую высоту `top-[calc(var(--top-bar-height,49px)+6px)]`, а не жёсткий `top-[54px]`.

### Архитектура и производительность (подробнее: `docs/agent/ARCHITECTURE.md`)
- Не блокировать первый рендер загрузкой всех 27 веток — сохранять базовый старт и фоновую догрузку.
- Не ломать `WeakMap`-кэширование аналитики в `src/engine/analytics/periodAnalytics.ts` и не мутировать возвращаемые массивы на месте.
- Не заменять ленивые вычисления (`concurrentEvents`) и O(N)-предрасчёт раскладки таймлайна на O(N²)-сканирование в рендере.
- Не добавлять внешние зависимости без явной необходимости; все новые модули покрывать тестами Vitest.

### Исторические данные (`public/data/`)
- Любое изменение JSON-веток обязано проходить `npm run validate:branches:strict`.
- После добавления/изменения веток синхронизировать каталог командой `npm run sync:catalog` и проверять `npm run sync:catalog:check`.

## 4. Правила совместной работы разных агентов

1. **Точечные правки**: меняйте только файлы, напрямую относящиеся к текущей задаче. Запрещено попутно переформатировать или «рефакторить» несвязанные рабочие файлы.
2. **Изоляция веток при параллельной работе**: используйте короткоживущие ветки по шаблону `agent/<среда>/<короткая-задача>` (например, `agent/codex/filter-fix`, `agent/gemini/era-dossier`). Не работайте одновременно двумя агентами в одной и той же группе файлов без синхронизации через `main`.
3. **Уважение к принятым решениям**: если пользователь просит изменить ранее утверждённое поведение, сначала обновите `docs/agent/DECISIONS.md` (пометьте старый ADR как `Заменён` и добавьте новый), затем вносите правки в код.
4. **Обязательная отметка о состоянии (`ADR-006`)**: после каждой решённой задачи обновите снимок состояния и добавьте **1 короткую запись** в начало `## Последние решённые задачи` в `docs/agent/HANDOFF.md` в формате `### YYYY-MM-DD · <Среда> · <Краткое название>`.
   - В `HANDOFF.md` хранится **не более 5 записей** (лимит — **160 строк**). Если записей стало больше 5, выполните `npm run handoff:rotate` — старые записи автоматически уйдут в `docs/agent/HANDOFF_ARCHIVE.md` (архив при обычном старте читать не нужно).
   - Обновление `HANDOFF.md` проверяется автоматически по `git diff` в `npm run verify` и Pull Request CI. Исключение `[skip-handoff]` допускается **только** для мелких опечаток — запрещено использовать его для обхода проверки на реальных задачах.

## 5. Обязательный шлюз проверки перед завершением задачи

Перед финальным ответом пользователю или коммитом выполните единую команду проверки:

```bash
npm run verify
```

Она последовательно запускает:

| Команда | Назначение |
| :--- | :--- |
| `npm run verify:invariants` | Проверка инструкций агентов, UI-инвариантов, лимитов и `git diff`-актуальности `HANDOFF.md` |
| `npm run validate:branches:strict` | Строгая валидация всех JSON-модулей исторических веток |
| `npm run sync:catalog:check` | Проверка актуальности `BRANCH_CATALOG.md` |
| `npm run lint` | Проверка типов TypeScript (`tsc --noEmit`) |
| `npm test` | Полный прогон модульных тестов (`vitest run`) |
| `npm run build` | Продакшн-сборка Vite |

Дополнительная сервисная команда: `npm run handoff:rotate` — переносит записи старше 5-й из `docs/agent/HANDOFF.md` в `docs/agent/HANDOFF_ARCHIVE.md`.

Задача считается завершённой только при полностью зелёном `npm run verify`.
