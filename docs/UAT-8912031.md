## 2. Критический блокер P0

### P0-01. Загрузчик сообщает о полноте при 0/23 и 22/23

**Место.** `src/engine/repository/timelineRepository.ts:575–586, 790–800, 823–836, 856–860, 889–891`; `src/hooks/useTimelineData.ts:30–42, 58–66, 79–103`. Ошибка HTTP, HTML вместо JSON или ошибка разбора превращаются в `null`. Флаг полного состояния зависит от факта попытки. Фоновая загрузка записывает `true` без проверки результата. При повторном обращении кэш немедленно возвращает этот снимок.

| HTTP при доступном манифесте | Получено файлов | Флаг «полностью загружено» | Запросы модулей после восстановления сети и приоритетного повтора |
|---|---:|---|---:|
| 503 для одного из 23 | 22 | да | 0 |
| 503 для всех 23 | 0 | да | 0 |

Обе строки воспроизведены в обоих режимах загрузки. Принудительная полная перечитка после восстановления сети вернула 23/23. Дополнительно вызов с `progressive:false` способен вернуть ранее закэшированный базовый срез при незавершённой догрузке.

**Как написано сейчас** — сокращённые фрагменты двух путей завершения.

```ts
const isFullyHydrated = initialPaths.length >= bootstrap.orderedCandidatePaths.length;
const fullSnapshot = buildSnapshotFromFiles(bootstrap, mergedFiles, true);
```

**Как должно быть написано** — пример общего правила завершения для обоих путей. Учёт ведётся по нормализованному пути запроса. В успешные результаты входят только провалидированные файлы. Для намеренно выключенного модуля ведётся отдельный учтённый статус.

```ts
const missingPaths = requiredPaths.filter(path => !acceptedPaths.has(path));
const isFullyHydrated = missingPaths.length === 0;
const snapshot = buildSnapshotFromFiles(bootstrap, files, isFullyHydrated);
return { ...snapshot, missingPaths };
```

**Критерий закрытия.** При 22/23 интерфейс сохраняет доступные материалы, показывает неполноту и даёт повторить отсутствующий запрос. При 0/23 показывает ошибку данных. После восстановления сети повтор доводит тот же сеанс до 23/23. Для обеих ветвей кода проверить также ответ HTML, неверный JSON, частичный кэш и два одновременных запроса. Полный запрос обязан дождаться полного снимка либо вернуть явный частичный результат с причиной.

**Клиентская безопасность.** В просмотренном приложении не найдены вызовы DOM-вставки через `innerHTML`/`dangerouslySetInnerHTML`, исполнение строк через `eval`/`new Function` или обработчики `postMessage`. В `src/utils/lazyWithRetry.ts:23–36` sessionStorage содержит метку времени повтора загрузки чанка. Локальное сканирование отслеживаемых файлов по сигнатурам приватных ключей и токенов GitHub, AWS и Google не дало совпадений. Единственная версионируемая env-заготовка `.env.example` описывает публичный `VITE_SITE_URL`. Этот результат относится к текущему дереву; историю удалённых секретов и фактический опубликованный бандл он не удостоверяет.

**Защита и доставка статики.** В `index.html:6–10` действует meta-CSP с `script-src 'self'` и `connect-src 'self'`. Для стилей разрешён `'unsafe-inline'`; приложение действительно использует динамические стили раскладки. Внешних скриптов или таблиц стилей с CDN, которым требовался бы SRI, в проверенном HTML нет. Шрифты поставляются локально. `src/components/ErrorBoundary.tsx:25–26` ограничивает отладочный вывод режимом DEV. В отслеживаемом дереве отсутствуют `.map`; в конфигурации Vite выпуск карт исходников явно не включён. Отсутствие лишних файлов и тестовых адресов в фактическом артефакте подлежит проверке по его содержимому.

**GitHub Pages, SEO и производительность.** `.github/workflows/deploy.yml:50–64` задаёт канонический URL и передаёт в Pages каталог `dist`. В репозитории есть `public/.nojekyll`, `404.html` и `og-image.png`; собственный домен и `CNAME` не заявлены. В `vite.config.ts` предусмотрены относительный `base`, разделение JS на чанки, формирование canonical, Open Graph, JSON-LD, robots.txt и sitemap.xml. Карта сайта содержит главную страницу. В `buildModulesIndexPayload` формируется хеш содержимого JSON, а `buildVersionedDataUrl` добавляет его к запросу. Проверить имена собранных JS/CSS и обновление после следующей выкладки можно только на артефакте. Наличие стартового HTML, ленивых досье и хешей данных учтено. Численные значения Core Web Vitals и контрастности в акте не присвоены.

**Типизация и модульность.** В `tsconfig.json:11–14` включены строгие проверки. В просмотренном прикладном TS/TSX явной опоры на `: any` и `as any` не выявлено. Изменения не добавили npm-зависимостей. Решение вынести модель хроники в отдельный файл позволяет проверять группировку на полном корпусе независимо от React. Наиболее дорогая граница сопровождения видна в `src/App.tsx` и `src/components/GitTimeline.tsx` — в каждом более 2 300 строк, а выбор веток, навигация и выбранная карточка поддерживаются несколькими механизмами. Конкретные последствия зафиксированы в P1-10–P1-13. Актуальный список advisory, наличие более свежих версий пакетов и результат полного аудита зависимостей из этой среды не подтверждены.
