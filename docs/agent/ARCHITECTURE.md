# Архитектура и контракты производительности (`ARCHITECTURE.md`)

Документ описывает устройство данных, аналитического движка и рендеринга таймлайна, чтобы разные агенты развивали кодовую базу согласованно и без деградации производительности.

---

## 1. Структура слоёв приложения

- `public/data/` — модульные исторические JSON-ветки и `sync.manifest.json`. Контракт формата описан в `BRANCH_SPEC.md`, живой реестр — в `BRANCH_CATALOG.md`.
- `src/types/timeline.ts` — центральные TypeScript-типы событий, веток, правителей, досье, сфер (`EraEventSphereId`) и сравнения периодов (`ComparisonSideSummary`).
- `src/engine/` — чистые функции обработки данных без зависимости от React:
  - `timelineEngine.ts` — фасад реэкспорта основных функций движка.
  - `analytics/periodAnalytics.ts` — расчёт досье правителей, макро-периодов, произвольных окон лет и сравнения периодов.
  - `nlp/personExtractor.ts` — нормализация имён, построение индекса деятелей (`buildPersonDossierIndex`) и O(1)-поиск `resolvePersonKey`.
  - `regionFilter.ts` — фасетная фильтрация и подсчёт событий по макрорегионам.
- `src/components/timeline/` — рендеринг ленты времени и предрасчёт геометрии дорожек (`timelineLayoutPrecompute.ts`).
- `src/components/` — верхняя панель (`TopControlBar`), поповеры навигации и аналитические модальные окна.
- `src/engine/__tests__/` — автоматические тесты Vitest на реальном датасете из `public/data/`.

## 2. Критические контракты производительности

1. **Прогрессивная неблокирующая загрузка 27+ веток**
   - При открытии сайта сначала поднимается базовый набор, чтобы интерфейс мгновенно стал интерактивным и кликабельным; остальные ветки догружаются в фоне без блокировки главного потока.
   - Запрещено возвращать синхронную блокировку всего интерфейса до загрузки всех JSON-файлов.

2. **`WeakMap`-кэширование аналитики**
   - `getRulerPeriodSummaryData`, `getMacroEraSummaryData` и `getCustomWindowSummaryData` используют `WeakMap`-кэширование, привязанное к ссылкам массивов данных и `personDossiers`.
   - Повторное открытие одного и того же окна должно возвращать ту же ссылку из кэша (`O(1)`).
   - Запрещено мутировать массивы/объекты, возвращаемые из аналитики, внутри React-компонентов (при сортировке или фильтрации в UI всегда создавайте копию).
   - Общая логика классификации по 5 сферам (`buildSphereEventsAndSummaries`) и группировки деятелей по 4 группам (`buildGroupedFigures`) переиспользуется между `getMacroEraSummaryData` и `getCustomWindowSummaryData` — не дублируйте её в UI-компонентах.

3. **Быстрые синхронные связи и поиск персон**
   - `ev.concurrentCount` вычисляется за O(N log N) через префиксные суммы, а `ev.concurrentEvents` является ленивым геттером. Не обращайтесь к `ev.concurrentEvents.length` в горячих циклах рендера — используйте `ev.concurrentCount`.
   - `resolvePersonKey` работает за O(1) через индекс — не перебирайте `dossiers.entries()` линейно.

4. **Линейный предрасчёт раскладки таймлайна**
   - `precomputeTimelineLayout` строит карту проходящих рельсов и активных слотов правителей за O(N). Не возвращайте по-строчный O(N²)-перебор событий внутри рендера каждой строки таймлайна.

## 3. Контракт работы с историческими данными

- Автообнаружение модулей работает через Vite-плагин — не требуется вручную править TypeScript для добавления новой ветки.
- При любом изменении `public/data/**/*.json`:
  1. Проверить соответствие `BRANCH_SPEC.md`.
  2. Запустить `npm run validate:branches:strict`.
  3. Обновить каталог через `npm run sync:catalog`.
  4. Проверить синхронность через `npm run sync:catalog:check`.

---

## 4. Контракт тестирования

- Любое изменение логики в `src/engine/` должно сопровождаться тестами в `src/engine/__tests__/`.
- Тесты используют реальный набор данных из `public/data/`, что гарантирует проверку не только синтетических примеров, но и целостности всех 27+ исторических веток.
- Все 42+ модульных теста должны проходить без предупреждений и пропусков (`npm test`).
